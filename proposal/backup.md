# Proposal: резервное копирование данных

**Статус:** предлагается к реализации  
**Приоритет:** низкий (два устройства дают встроенную избыточность)  
**Затрагивает:** `AndroidManifest.xml`, `SettingsScreen.kt`, `SettingsViewModel.kt`, `res/xml/`

---

## Контекст

Приложение хранит все данные локально на двух устройствах. Два устройства — уже встроенная защита от потери: пока одно живо, задачи не теряются. Критичный сценарий — оба телефона вышли из строя одновременно (поломка, кража, сброс до заводских настроек).

---

## Что бекапить

| Данные | Где хранится | Важность |
|---|---|---|
| Задачи и tombstone-ы | Room DB (`family_tasks_database`) | Критично |
| `deviceId` | SharedPreferences | Важно — потеря = потеря идентичности, нужен повторный QR-паринг |
| `pairedDeviceId` | SharedPreferences | Важно — без него не восстановить связь |
| `displayName`, `avatarColor` | SharedPreferences | Низкая — легко ввести заново |
| `lastKnownPeerIp`, `lastConfirmedSyncTimestamp` | SharedPreferences | Не нужно — переоткрываются сами |

## Варианты реализации

### Вариант A — Android Auto Backup (минимальные усилия)

Android автоматически бекапит `/databases/` и `/shared_prefs/` в Google Drive (до 25 МБ, бесплатно). Нужно только убедиться, что в манифесте включено, и при необходимости добавить `backup_rules.xml` для исключения ненужного.

**Что делать:**

1. Убедиться, что `android:allowBackup="true"` в `<application>` манифеста.
2. Добавить `res/xml/backup_rules.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<full-backup-content>
    <include domain="database" path="family_tasks_database" />
    <include domain="sharedpref" path="family_tasks_prefs.xml" />
</full-backup-content>
```

3. Подключить в манифесте:

```xml
android:fullBackupContent="@xml/backup_rules"
android:dataExtractionRules="@xml/data_extraction_rules"
```

`data_extraction_rules.xml` — то же содержимое, применяется на Android 12+.

**Плюсы:** почти нулевые усилия, работает автоматически, прозрачно для пользователя.  
**Минусы:** требует Google-аккаунт, пользователь не контролирует момент бекапа, бекап может быть до 24 ч устаревшим.

---

### Вариант B — Ручной экспорт (кнопка в настройках)

Кнопка «Экспортировать данные» в разделе «Настройки». Копирует файл БД во временный кэш и отдаёт через Share Sheet — пользователь сам выбирает куда (файловый менеджер, облако, мессенджер).

**Что делать:**

1. В `SettingsViewModel` — метод `exportDatabase()`:
   - Копирует `/data/data/<package>/databases/family_tasks_database` в `cacheDir/backup/family_tasks_backup.db`.
   - Отдаёт `Uri` через `FileProvider`.
2. В `SettingsScreen` — кнопка с обработчиком `startActivity(Intent.ACTION_SEND)`.
3. `FileProvider` прописать в манифесте (если ещё не добавлен для Share лога — уже есть `cache/logs/`).

Для восстановления — отдельный экран или диалог с предупреждением ("все текущие данные будут заменены").

**Плюсы:** пользователь контролирует момент и место хранения, работает без Google.  
**Минусы:** ручное действие, легко забыть; восстановление требует осознанного шага.

---

### Вариант C — Комбинация A + B (рекомендуется)

Auto Backup — страховка по умолчанию, работает без действий пользователя. Ручной экспорт — для тех, кто хочет контроль (например, перед заменой телефона). Усилия: ~A + ~B.

---

## Порядок реализации (для варианта C)

1. Включить Auto Backup: манифест + два XML-файла правил (30 мин).
2. Проверить, что `FileProvider` для `cache/` уже объявлен (используется для Share лога).
3. Добавить `exportDatabase()` в `SettingsViewModel`.
4. Добавить кнопку в `SettingsScreen` рядом с секцией «Диагностика».
5. Опционально: диалог восстановления из файла.

---

## Ограничения

- При восстановлении из бекапа на новом устройстве `deviceId` будет старым — это **желательно**, чтобы партнёр узнал устройство без повторного QR.
- Auto Backup не гарантирует актуальность на момент поломки (задержка до 24 ч).
- Файл БД нельзя копировать пока Room держит транзакцию; нужно использовать `RoomDatabase.close()` или WAL checkpoint перед копированием, либо использовать `RoomDatabase.createDatabaseBackup()` (API 33+) — для широкой совместимости лучше WAL checkpoint.
