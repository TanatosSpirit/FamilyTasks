# Предложение: удалённая синхронизация между устройствами

**Статус:** частично реализован (вариант 1 реализован)  
**Контекст:** партнёры длительное время находятся в разных местах (разные WiFi-сети). Текущая архитектура работает только в одной подсети. Цель — периодическая синхронизация задач (например, раз в неделю) без изменения офлайн-first подхода приложения.

---

## Варианты реализации

### 1. Share JSON файлом через мессенджер ✅ реализовано

**Экспорт:** Настройки → «Поделиться задачами» → Android Share Sheet → файл `familytasks_export.json` в Telegram/WhatsApp.  
**Импорт:** партнёр открывает файл из мессенджера → «Открыть в FamilyTasks» → автоматический merge → Toast «Получено X задач от [имя]».

Использует тот же `SyncPayload` формат и `MergeTasksUseCase` что и WiFi-sync. Повторяющиеся задачи, уведомления и логи работают идентично. Delta sync и tombstone purge не применяются — экспорт всегда полный снимок, purge откладывается до следующего WiFi-синка.

**Затронутые файлы:** `ExportImportManager.kt` (новый), `SettingsViewModel`, `SettingsScreen`, `MainActivity`, `file_paths.xml`, `AndroidManifest.xml`.

- **Сложность кода:** минимальная
- **Настройка пользователем:** никакой
- **Приватность:** высокая
- **Одновременность:** не нужна — полностью асинхронно

---

### 2. Tailscale / ZeroTier (виртуальная локальная сеть)

Оба устройства вступают в одну виртуальную сеть — с точки зрения приложения это та же WiFi-подсеть. SubnetScanner найдёт партнёра как обычно. Нулевые изменения в коде, несколько минут настройки на телефонах.

- **Сложность кода:** нулевая
- **Настройка пользователем:** установить Tailscale на оба телефона
- **Приватность:** высокая
- **Одновременность:** пограничный случай — sync происходит автоматически как только оба окажутся онлайн одновременно; заранее договариваться не нужно, но пересечение окон онлайна необходимо

---

### 3. WireGuard

То же что Tailscale, но open-source и без центрального сервера компании. Сложнее в настройке.

- **Сложность кода:** нулевая
- **Настройка пользователем:** ручная настройка WireGuard на обоих телефонах
- **Приватность:** максимальная
- **Одновременность:** та же что Tailscale

---

### 4. Telegram Bot как relay

Бот — relay: устройство A постит зашифрованный JSON в чат с ботом, устройство B периодически опрашивает чат и делает merge. Бонус: бот может дополнительно слать человекочитаемый дайджест — «У партнёра 3 новых задачи: купить хлеб, позвонить врачу...»

- **Сложность кода:** средняя
- **Настройка пользователем:** зарегистрировать бота через @BotFather
- **Приватность:** средняя (Telegram видит трафик, если нет E2E шифрования поверх)
- **Одновременность:** не нужна — полностью асинхронно (store-and-forward)

---

### 5. Email как шина

Отправляешь себе письмо с JSON-вложением через Gmail API, партнёр тянет и делает merge. Примитивно, но email никуда не денется.

- **Сложность кода:** малая
- **Настройка пользователем:** OAuth для Gmail API
- **Приватность:** средняя
- **Одновременность:** не нужна — полностью асинхронно

---

### 6. Encrypted pastebin

Шифруешь JSON симметричным ключом (общий секрет — paired deviceId или отдельный ключ при сопряжении), постишь на `paste.rs` или `0x0.st`, отправляешь партнёру короткую ссылку. Партнёр скачивает, дешифрует, merge. Ни один сервер не видит содержимое.

- **Сложность кода:** малая
- **Настройка пользователем:** никакой
- **Приватность:** высокая (E2E шифрование)
- **Одновременность:** не нужна — но ссылку нужно передать через мессенджер (гибрид)

---

### 7. ntfy.sh

Push-уведомления с произвольным payload. Один топик на пару устройств, зашифрованный JSON в теле — асинхронный push без polling.

- **Сложность кода:** малая
- **Настройка пользователем:** никакой
- **Приватность:** средняя
- **Одновременность:** не нужна — store-and-forward до доставки
- **Ограничение:** бесплатный лимит 4 КБ на сообщение → нужен delta sync

---

### 8. Cloudflare Tunnel / ngrok

Одно устройство открывает туннель — его HttpServer на :8080 становится доступен снаружи по временному URL. Второй партнёр делает обычный POST /sync на этот URL. Туннель можно поднять вручную перед «сеансом синка».

- **Сложность кода:** малая (добавить поле «URL партнёра» в настройки)
- **Настройка пользователем:** установить cloudflared или ngrok на одном телефоне
- **Приватность:** средняя (трафик через серверы Cloudflare/ngrok)
- **Одновременность:** одностороннее требование — устройство с туннелем должно быть онлайн и держать туннель, второй подключается когда хочет

---

### 9. Tiny relay-сервер (E2E)

Минималистичный сервер на Fly.io / Railway (бесплатный tier). Хранит только последний зашифрованный SyncPayload от каждого deviceId. A делает `PUT /relay/{pairedId}`, B делает `GET /relay/{myId}` — забирает и сервер чистит. Сервер не знает содержимое (E2E шифрование), не хранит историю.

- **Сложность кода:** средняя (HttpClient + серверная часть)
- **Настройка пользователем:** никакой (сервер общий)
- **Приватность:** высокая (E2E)
- **Одновременность:** не нужна — идеальный store-and-forward

---

### 10. WebRTC Data Channel (P2P через интернет)

Оба устройства договариваются через сигнальный сервер, потом устанавливают P2P соединение напрямую через NAT (STUN/TURN). После handshake гоняют тот же sync JSON без посредника.

- **Сложность кода:** большая
- **Настройка пользователем:** никакой
- **Приватность:** максимальная (истинный P2P)
- **Одновременность:** **обязательна** — P2P handshake требует присутствия обоих

## Классификация по оси «одновременность»

### Полностью асинхронные (store-and-forward)

Один кладёт данные в «буфер», второй забирает когда удобно. Ключевое: есть посредник, который хранит данные между отправкой и получением.

- Share JSON файлом
- Telegram Bot
- Email
- Encrypted pastebin
- ntfy.sh
- Tiny relay-сервер

### Один онлайн как сервер

Один держит соединение открытым, второй подключается в любой момент пока сервер жив.

- Cloudflare Tunnel / ngrok

### Нужно пересечение окон онлайна

Sync происходит автоматически при совпадении, но без совпадения — не происходит. Заранее договариваться не нужно, но оба должны быть в сети одновременно хоть на минуту.

- Tailscale / ZeroTier
- WireGuard

### Требуют одновременного присутствия обоих

- WebRTC P2P

## Рекомендации к рассмотрению

**Наименьшие затраты:** Share JSON файлом — реализовано. Переиспользует весь существующий merge-движок, пользователь получает знакомый интерфейс Share Sheet.

**Без изменений кода:** Tailscale / ZeroTier — если пользователи готовы поставить стороннее приложение.

**Лучший баланс (если писать код):** Tiny relay-сервер — асинхронный, E2E, без настройки со стороны пользователя, расширяет существующий HttpClient минимально.

**Максимальная приватность:** WebRTC P2P, но требует наибольших усилий и синхронного присутствия.
