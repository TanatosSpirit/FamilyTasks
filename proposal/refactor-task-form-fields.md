# Предложение: вынести общую форму задачи в TaskFormFields

## Контекст

`CreateTaskScreen.kt` и `EditTaskContent.kt` содержат ~80 одинаковых строк — поля формы задачи. Дублирование обнаружилось при добавлении `KeyboardCapitalization.Sentences`: правку пришлось вносить в оба файла. Это стандартный сигнал к рефакторингу.

## Что предлагается

Выделить `@Composable fun TaskFormFields(...)` — общий блок полей без Scaffold и логики сабмита. Оба экрана подключают его, сохраняя свою структуру.

### Что войдёт в TaskFormFields
- поля «Название» и «Описание» (`OutlinedTextField`)
- выбор приоритета (чипы)
- блок «Назначить» (с логикой isSecret)
- строка дедлайна + `pickDateTime()`
- выбор повторения
- переключатель «Секретная задача»
- опционально: выбор статуса (только для Edit, параметр `showStatus: Boolean`)

### Что остаётся в каждом экране отдельно
- `CreateTaskScreen` — `Scaffold` + `TopAppBar` + кнопка «Создать» + вызов `vm.save(...)`
- `EditTaskContent` — голый `Column` + кнопки «Сохранить»/«Отмена» + `task.copy(...)`

## Плюсы

- **Правка в одном месте.** Добавление поля, стиля или поведения (как сегодня с капитализацией) не требует синхронизировать два файла.
- **Консистентность гарантирована структурно.** Сейчас «Приоритет» в Create использует `MaterialTheme.typography.titleSmall`, а в Edit — просто `Text("Приоритет")` без стиля. После рефакторинга такие расхождения невозможны.
- **Новые поля добавляются один раз.** Появится поле «Метки» или «Цвет» — достаточно добавить в `TaskFormFields`.

## Минусы

- **Сигнатура компонента будет широкой.** ~10 параметров: значения полей, колбэки на изменение, `devices`, `myDeviceId`, `showStatus`. Читать чуть сложнее, чем два самостоятельных компонента.
- **Экраны расходятся — рефакторинг устаревает.** Если Create получит черновики или шаблоны, а Edit — историю изменений, общий компонент начнёт «пухнуть» от флагов. Придётся снова разделять.
- **Риск при неаккуратном выполнении.** `pickDateTime()` в Edit инициализирует `cal` из `dueDate`, в Create — нет. Мелкие различия легко потерять при слиянии.

## Когда делать

Отдельным коммитом на чистой ветке, без соседних функциональных правок — иначе сложно ревьюить и откатывать.

## Оценка объёма

Один файл новый (`TaskFormFields.kt`), правки в двух существующих. Около часа работы плюс ручная проверка обоих экранов на устройстве.
