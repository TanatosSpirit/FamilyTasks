# Свайп для завершения задачи

Активные задачи в списке можно завершить свайпом карточки в любую сторону — без открытия экрана задачи. При свайпе открывается зелёный фон с иконкой галочки; в момент пересечения порога срабатывает тактильный отклик, задача переходит в статус `DONE` и пропадает из активного списка.

---

## Поведение

- Свайп влево или вправо — результат одинаковый, завершение задачи.
- Работает только для задач со статусом `TODO`. На вкладке «Готово» карточки не свайпаются.
- Задача пропадает из списка сразу — `statusFilter == ACTIVE` отфильтровывает её как только статус меняется на `DONE`.
- Если пользователь не дотянул до порога и отпустил — карточка возвращается на место, задача не меняется.

---

## Визуальная обратная связь

Фон нарастает линейно от начала свайпа до порога, затем вспыхивает до сплошного зелёного в момент срабатывания.

| Момент | Непрозрачность фона |
|---|---|
| Старт свайпа (0%) | 0.20 |
| Середина (25%) | 0.55 |
| Порог (50%) | 0.90 |
| После порога | **1.0** (мгновенный скачок) |

Формула до порога: `alpha = (0.20 + fraction * 1.4).coerceIn(0, 0.9)`, где `fraction = rawOffset / cardWidth`.

Иконка галочки фейдит пропорционально фону: `iconAlpha = (bgAlpha / 0.9).coerceIn(0, 1)`.

Сырой пиксельный сдвиг берётся через `dismissState.requireOffset()`. Ширина компонента захватывается через `onSizeChanged` на `SwipeToDismissBox`.

---

## Тактильный отклик

В момент пересечения порога (50% ширины карточки) вызывается `view.performHapticFeedback(HapticFeedbackConstants.CLOCK_TICK)` — самый лёгкий системный тип, ощущается как короткий физический щелчок.

Срабатывает ровно один раз за жест: `LaunchedEffect(pastThreshold)` с флагом `prevPastThreshold` защищает от повторного вызова при возврате и повторном пересечении порога в рамках одного свайпа.

---

## Порог срабатывания

Стандартный порог `SwipeToDismissBox` из Material3 — **50% ширины карточки** (`SwipeToDismissBoxDefaults.positionalThreshold`). Не переопределяется.

`targetValue != SwipeToDismissBoxValue.Settled` — сигнал того, что порог пересечён. Именно на это значение подписан `LaunchedEffect` для вибрации и ветка `bgAlpha = 1f`.

## Реализация

**`TaskListScreen.kt`** — composable `SwipeableTaskCard` оборачивает `TaskCard` в `SwipeToDismissBox`. Используется вместо `TaskCard` в `LazyColumn` только для `task.status == TaskStatus.TODO`.

**`TaskListViewModel.kt`** — метод `completeTask(task: Task)`:
1. Проверяет `task.status != DONE` (guard от двойного вызова).
2. Если задача — активная повторяющаяся, назначенная на себя (`isRecurringEligible`), не завершает её сразу, а кладёт в `_pendingRecurrenceTask` — пользователь должен выбрать «Завершить текущую» / «Завершить цепочку» в диалоге (`docs/recurring-completion-choice.md`).
3. Иначе — сразу вызывает `RecurringTaskCompletionUseCase.completeEndingChain(task)`: `status = DONE`, `updatedAt`/`completedAt = now`, отмена due-уведомлений и `RecurrenceSpawn`.
4. Логирует через `AppLogger.d`.

`completedAt` проставляется по той же конвенции, что и в `TaskDetailViewModel.cycleStatus()`.

Для eligible-повторяющихся задач сам жест не завершает свайп — `confirmValueChange` возвращает `false`, карточка возвращается на место, пока не будет принято решение в диалоге. Подробности — `docs/recurring-completion-choice.md`.

---

## Ограничения

- Повторяющиеся задачи, назначенные на себя (`recurrence != None`, есть `dueDate`), свайпаются не мгновенно — сперва диалог выбора продолжения цепочки, см. `docs/recurring-completion-choice.md`. Повторяющиеся задачи, назначенные партнёру, и обычные задачи свайпаются как раньше — мгновенно.
- Секретные задачи (`isSecret = true`) свайпаются без ограничений — `isSecret` не влияет на логику завершения.
- Undo не предусмотрен: задачу можно открыть через вкладку «Готово» и вернуть вручную.
