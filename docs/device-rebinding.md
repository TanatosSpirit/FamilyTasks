# Перепривязка задач при смене партнёра

## Проблема

`deviceId` — идентичность **установки**, а не человека. После переустановки приложения устройство получает новый id, но задачи (`assignedTo`, `createdBy`) у обоих партнёров продолжают ссылаться на старый. Симптомы:

- не приходят due-уведомления и не срабатывает спавн повторов (условие `assignedTo == myDeviceId`);
- фильтр «мои задачи» пустой;
- в списке «назначить» два одинаковых имени: старый id живёт в таблице `devices` и, до этого изменения, возвращался при каждом sync через `buildDevicesPayload()` партнёра.

Усугублял ситуацию Android Auto Backup: он восстанавливал базу Room (вместе с секретными задачами), но не `device_prefs.xml` — задачи возвращались, идентичность нет.

## Решение

### 1. Инвариант таблицы `devices`

В `devices` только мы и текущий `pairedDeviceId`. Поддерживается двумя правилами:

- `SyncUseCase.mergeAll()` сохраняет из входящего списка устройств **только** запись `pairedDeviceId`; остальные игнорируются (лог `Merge: ignoring foreign device`).
- При сопряжении все прочие записи удаляются (см. ниже).

### 2. Перепривязка при сопряжении (`PairDeviceUseCase`)

`formerPartners(newId)` = { прежний `pairedDeviceId` } ∪ { все id из `devices` } − { свой id, `newId` }.

Если список не пуст — `QrCodeScreen` показывает диалог «Сменить партнёра?» с именами. После подтверждения `pair()`:

1. `TaskDao.reassignDevice(formerIds, newId, now)` — одним `UPDATE` меняет `assignedTo` и `createdBy`, поднимает `updatedAt`, чтобы версии победили по LWW у нового партнёра. Затрагивает и секретные задачи (локально).
2. Удаляет бывших партнёров из `devices`.
3. Очищает `task_sync_state` и сбрасывает `lastConfirmedSyncTimestamp = 0` — подтверждения относились к прежнему устройству, новому уйдёт полный снимок.
4. Сохраняет нового партнёра и `pairedDeviceId`.

Порядок шагов идемпотентен: если процесс упадёт до записи `pairedDeviceId`, повторный скан QR повторит перепривязку.

Due-уведомления не перепланируются: перепривязка меняет только id **партнёра**, eligibility «назначено на меня» не меняется.

Неважно, тот же это человек после переустановки или другой — задачи прежнего партнёра переходят к новому. Диалог нужен потому, что действие необратимо.

### 3. Системный бэкап выключен

`android:allowBackup="false"`, а `data_extraction_rules.xml` исключает все домены и для `cloud-backup`, и для `device-transfer` (на Android 12+ перенос между устройствами игнорирует `allowBackup`). Причины:

- восстановление БД без `device_prefs` даёт задачи со «старым собой»;
- восстановление вместе с `device_prefs` на втором телефоне даёт клон `deviceId` — ломает self-loop detection;
- секретные задачи не должны уходить в облако без решения пользователя.

Замена — ручной бэкап через приложение: `docs/manual-backup.md`.

## Сценарий: партнёр переустановил приложение

1. B переустановил → новый id `B2`, задачи пусты.
2. A и B сканируют QR друг друга. У A: `formerPartners = [B1]` → диалог → задачи `B1 → B2`, `updatedAt` поднят.
3. Sync: B2 получает всё (кроме секретных задач A) уже с правильными id.
4. Секретные задачи B потеряны, если не было ручного бэкапа. Если был — B восстанавливает его, и `RestoreBackupUseCase` переписывает `B1 → B2` в задачах из файла.

## Ограничение

Правило «всё, кроме себя и текущего партнёра — бывший партнёр» верно, пока инвариант соблюдается. Базы, собранные до этого изменения, могут содержать в `devices` **собственный** прежний id (после восстановления из Auto Backup). Пересканирование QR на таком устройстве предложит перенести «себя» к партнёру — имя в диалоге это покажет, нужно нажать «Отмена».

### Ручное «Это моё прежнее устройство» (`FormerSelfUseCase`)

Настройки → Диагностика → «Лишние устройства» (секция видна, только если такие есть): записи `devices`, кроме себя и `pairedDeviceId`, с числом ссылающихся задач. Кнопка после подтверждения:

1. `reassignDevice([oldId], selfId, now)` — `assignedTo` и `createdBy` во всех задачах, включая секретные и tombstone-ы; поднятый `updatedAt` разносит исправления партнёру.
2. Удаляет `oldId` из `devices`.
3. Для задач, которые стали «моими» и активны, планирует due-напоминания и спавн повторов.

Автоматически отличить свой прежний id от бывшего партнёра нельзя, поэтому действие ручное. Автоочистка записей без ссылок сознательно не сделана: после фильтра в `mergeAll` и перепривязки при сопряжении таким записям неоткуда взяться, а если появятся — та же кнопка удалит запись (переписывать нечего).
