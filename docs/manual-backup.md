# Ручная резервная копия

Настройки → «Резервная копия» → «Сохранить резервную копию» / «Восстановить из копии». Файл выбирается через системный диалог (SAF): `CreateDocument` / `OpenDocument`, место выбирает пользователь — локальная папка, Google Drive, мессенджер.

Заменяет системный Auto Backup, который выключен (`docs/device-rebinding.md`).

## Формат (`BackupManager.kt`)

```json
{
  "format": "familytasks-backup",
  "version": 1,
  "createdAt": 1760600000000,
  "self":    { "deviceId": "aaa-111", "displayName": "Андрей", "color": -12345678 },
  "partner": { "deviceId": "bbb-222", "displayName": "Мама",   "color": -8765432 },
  "tasks": [ { "task": { ...TaskDto... }, "isSecret": true } ]
}
```

- Отдельный формат, не `SyncPayload`: `TaskDto` намеренно не содержит `isSecret`, поэтому задача обёрнута в `BackupTaskDto(task, isSecret)`.
- Все задачи как есть, включая секретные и tombstone-ы.
- `self` и `partner` — id **на момент копии**. На них строится перепривязка при восстановлении.
- **Файл не зашифрован.** Шифрование паролем отложено на потом.

## Восстановление (`RestoreBackupUseCase`)

1. **Защита:** если `self.deviceId` копии равен текущему `pairedDeviceId`, это копия партнёра, она отклоняется.
2. **Перепривязка id** в `assignedTo` / `createdBy`:
   - `backup.self` → текущий `deviceId`;
   - `backup.partner` → текущий `pairedDeviceId` (если сопряжены и id отличается).
3. **Слияние по LWW с исходными `updatedAt`** — их не поднимаем. Если партнёр уже прислал перепривязанные версии (`PairDeviceUseCase` поднимает `updatedAt`), они свежее и побеждают копию. Tombstone неизвестной задачи не воскрешается (как в `MergeTasksUseCase`).
4. **Устройства:** запись `backup.self` удаляется из `devices` (если отличается от текущего id). Если партнёр ещё **не** сопряжён, `backup.partner` кладётся в `devices`, и при будущем сопряжении `PairDeviceUseCase` распознает его как бывшего и предложит перепривязку.
5. **`lastConfirmedSyncTimestamp = 0`**, если что-то записано: восстановленные задачи могут быть старше watermark-а, и delta-sync их бы не отправил.
6. **Уведомления:** для записанных задач due-напоминания и `RecurrenceSpawnWorker` планируются или отменяются по обычному условию (`assignedTo == me && status != DONE && !deleted`). `notifyNewTask` не показывается.

Восстановление идемпотентно: повторное применение того же файла даст «без изменений».

`task_sync_state` не трогается: восстановленные задачи партнёр ещё не подтверждал, индикатор pending-sync для них корректен.

## Сценарий: переустановка

1. До переустановки: «Сохранить резервную копию».
2. Переустановка → новый id. Онбординг, сопряжение по QR на обоих телефонах. У партнёра диалог «Сменить партнёра?» → задачи перепривязываются на новый id.
3. Sync приносит общие задачи.
4. «Восстановить из копии» → возвращаются секретные задачи и всё, что не успело уйти партнёру. Id в них переписаны на текущие.

Порядок шагов 2–4 можно менять: восстановление до сопряжения тоже работает (партнёр из копии попадёт в `devices` и будет перепривязан при сопряжении).

## Что не входит в копию

Настройки (`device_prefs`): имя, цвет, тумблеры уведомлений, ежедневная сводка. Имя и цвет записаны в `self` для будущего использования, но не восстанавливаются: они задаются в онбординге.
