# Веб-интерфейс (экспериментально, без аутентификации)

Возможность посмотреть список задач и добавить/завершить задачу с компьютера через браузер, не беря в руки телефон, который лежит в той же WiFi-сети.

## Проблема

Телефон уже держит открытым HTTP-сервер на порту 8080 для WiFi-синхронизации (`docs/architecture.md`). Хочется иногда посмотреть или добавить задачу с ПК, но городить отдельное приложение под каждую ОС — избыточно для семейного приложения на два устройства.

## Решение — минимальный веб-клиент поверх существующего сервера

`HttpServer` (тот же, что обслуживает `/identify` и `/sync`) получил четыре новых маршрута, отдающих HTML-страницу и простой JSON API поверх `TaskRepository`. Новый код ничего не знает про сопряжение и работает поверх произвольного браузера в локальной сети.

**Аутентификации нет вообще.** Это осознанное решение первой итерации — сначала отладить основной сценарий (посмотреть/добавить/отметить готово), полноценный пейринг браузера (QR/токен, ревокация сессий) — отдельная задача на будущее, обсуждалась в переписке, но пока не реализована.

## Экспериментальный тумблер — по умолчанию выключен

Настройки → «Экспериментальные фичи» → «Веб-интерфейс без аутентификации (только в надёжной сети!)». Хранится в `PreferencesManager.webUiEnabled` (+ `webUiEnabledFlow`), default `false`.

Тумблер гейтит **сами маршруты**, не только UI: `HttpServer` проверяет `isWebUiEnabled()` в `serve()` на каждый из новых запросов и при `false` отвечает `404 Not Found` — то есть при выключенном тумблере веб-маршруты неотличимы от несуществующих, порт 8080 продолжает обслуживать только штатный sync-протокол.

Когда тумблер включён, под ним показывается адрес для браузера: `http://<lastKnownOwnIp>:8080/web` (поле уже существовало в `PreferencesManager` для диагностики) и предупреждение красным текстом — что пока включено, любой в этой WiFi-сети может смотреть и менять задачи без пароля.

## Ожидаемый сценарий использования

1. Пользователь дома, телефон в той же WiFi-сети, лежит где-то в другой комнате.
2. На телефоне (заранее или в моменте) включается тумблер — это осознанное разовое действие, означающее «сейчас я уверен, что сеть безопасна».
3. На компьютере в браузере открывается `http://<IP-телефона>:8080/web`.
4. В браузере видно список активных задач (без секретных и без удалённых), можно:
   - добавить новую задачу (название, описание, приоритет, срок, назначить партнёру или себе);
   - отметить задачу выполненной или вернуть в работу.
5. Изменения сразу пишутся в локальную БД телефона и уходят партнёру обычным путём: `taskRepository.upsertTask()` триггерит `observeTaskChanges()` → `triggerSync()` (debounce 3с) — отдельного кода для доставки партнёру не потребовалось.
6. После того как сессия работы закончена, тумблер стоит выключить обратно — редактирование/просмотр форм ничем не защищены, пока он включён.

Страница не запоминает состояние тумблера и не предлагает его переключить дистанционно — включать нужно на самом телефоне.

## API

Все — только при `isWebUiEnabled() == true`, иначе `404`.

| Маршрут | Назначение |
|---|---|
| `GET /web` | HTML-страница (`assets/webui.html`, читается в `SyncService.startHttpServer()` один раз при старте сервиса) |
| `GET /api/tasks` | `SyncPayload` (тот же формат, что и `/sync`) — задачи без `isSecret`/`deleted` + список устройств для отображения имён `assignedTo` |
| `POST /api/tasks` | тело `WebCreateTaskRequest` (title/description/priority/dueDate/assignedTo) → создаёт задачу через `taskRepository.upsertTask()` |
| `POST /api/tasks/{id}/toggle` | переключает `status` todo↔done, выставляет/сбрасывает `completedAt`, планирует/отменяет due-уведомления и recurrence-spawn — повторяет логику `TaskDetailViewModel.cycleStatus()` |

`isSecret`-задачи никогда не появляются в `/api/tasks` и не могут быть созданы через веб-форму — тот же принцип, что и для WiFi-sync payload (`docs/secret-tasks.md`).

## Осознанно не сделано в первой версии

- **Аутентификация** — главный риск: пока тумблер включён, любое устройство в той же WiFi-сети может просматривать и менять задачи, включая партнёра (если он не должен видеть какое-то изменение раньше времени — например сюрприз). Смягчается только тем, что тумблер выключен по умолчанию и требует явного действия на телефоне перед каждым использованием.
- Редактирование и удаление задач с веба.
- Recurrence (повторяющиеся задачи) при создании через веб-форму — новая задача всегда создаётся с `recurrence = None`.
- HTTPS/шифрование — тот же cleartext HTTP, что и у остального sync-протокола (`network_security_config`, `docs/architecture.md`).

## Известное упрощение: дублирование due-notification логики

`onWebToggleTask` в `SyncService.kt` повторяет `applyDueNotificationState`/`cycleStatus` из `TaskDetailViewModel.kt` — расчёт `eligible` (assignedTo == я, status != DONE, !deleted) и schedule/cancel due-уведомлений и recurrence-spawn продублирован. Это уже четвёртое место с такой логикой (после `TaskDetailViewModel`, `CreateTaskViewModel`, `MergeTasksUseCase`) — общий helper не заводился сознательно, чтобы не переусложнять debug-фичу; если логика будет меняться, проверять все четыре места.
