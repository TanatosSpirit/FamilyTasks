# Достижимость в фоне — Doze, Samsung One UI и keepAlive

Почему заблокированный телефон перестаёт отвечать партнёру и что с этим сделано. Краткая
выжимка — в CLAUDE.md, раздел «Разрешения»; здесь полный разбор и ручной чек-лист.

---

## Проблема: Foreground Service не спасает от Doze

Foreground Service **не выводит приложение из Doze** и не держит CPU/WiFi. Когда телефон
заблокирован и неподвижен, наступает Doze:

- CPU уходит в suspend — accept-loop NanoHTTPD не выполняется;
- сеть для приложения замораживается;
- WiFi-радио уходит в power-save.

Итог — заблокированный на часы телефон перестаёт отвечать партнёру на `/identify` и `/sync`.

---

## Решение: keepAlive через AlarmManager

`keepAlive` реализован через `AlarmManager.setExactAndAllowWhileIdle()` — в отличие от
`delay()` в корутине, этот будильник срабатывает даже в Doze. Каждое срабатывание выводит CPU
и WiFi из сна на ~1–2 сек (один GET /identify), после чего устройство возвращается в Doze.
Стоимость 8 пробуждений за ночь — порядка 0.3–0.5 мАч (на 4 порядка меньше MulticastLock).

**Реализован уровень 1 (Doze whitelist, минимум по батарее).** Это сознательный выбор:
`WifiLock`/`WakeLock` **не используются** как постоянные, чтобы не возвращать постоянный расход
батареи (ср. удалённый MulticastLock, ~600 мАч/сутки). Жёсткой гарантии «отклик в любую
миллисекунду» нет — WiFi power-save может добавлять задержку на пробуждение или редкий обрыв
входящего соединения. Если потребуется надёжнее — следующий шаг это
`WifiLock(WIFI_MODE_FULL_HIGH_PERF)` (уровень 2) и постоянный partial `WakeLock` (уровень 3),
оба ценой батареи.

> Короткоживущие `PARTIAL_WAKE_LOCK` на время scan и retry-цикла identify — это не уровень 3,
> а защита уже выполняющейся корутины от Doze. См. `docs/conventions-rationale.md`.

### Что есть в коде

- `AlarmManager.setExactAndAllowWhileIdle()` для keepAlive — срабатывает в Doze, цепочка:
  `KeepAliveReceiver` → `SyncService.ACTION_KEEPALIVE` → `performKeepAlive()`.
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` в манифесте.
- Секция «Фоновая работа» в `SettingsScreen` — показывает статус
  `PowerManager.isIgnoringBatteryOptimizations()` и кнопку, открывающую системный диалог
  (`Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`). Статус перечитывается на `ON_RESUME`
  (диалог не возвращает результат).

## Ручной чек-лист на ОБОИХ телефонах

Без него код бессилен — One UI замораживает агрессивнее, чем перекрывает Doze-whitelist.

1. Приложение → Настройки → Фоновая работа → «Отключить оптимизацию батареи».
2. Настройки телефона → Приложения → FamilyTasks → Батарея → **«Без ограничений»**.
3. Настройки → Батарея → Ограничения фоновой активности → добавить в **«Никогда не отправлять
   в сон»**; убрать из «Спящих»/«Глубоко спящих».
4. Настройки → Батарея → выключить **«Переводить неиспользуемые приложения в сон»** (или
   исключить приложение).

Пункты 2–4 из кода недоступны — только пользователь руками. Метки в One UI 8.5 могут чуть
отличаться.
