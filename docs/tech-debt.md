# Технический долг

Накопился при работе над перепривязкой устройств и ручным бэкапом (`docs/device-rebinding.md`, `docs/manual-backup.md`).

## Безопасность

1. **`POST /sync` принимает задачи от любого отправителя.** `SyncService.kt`, `onSyncRequest`: проверка `incoming.deviceId == pairedDeviceId` защищает только сохранение IP, а `syncUseCase.mergeAll(...)` вызывается безусловно. Любое устройство в WiFi-сети может записать задачи в базу. Фильтр устройств в `mergeAll` закрывает только мусорные записи в `devices`, не задачи. Исправление: вызывать `mergeAll` и отдавать ответ только при совпадении `pairedDeviceId`.
2. **Файл резервной копии не зашифрован.** Секретные задачи в нём открытым текстом. Отложено: шифрование паролем (AES-GCM, ключ через PBKDF2). Цена — пароль, который можно забыть.

## Надёжность

3. **`QrCodeViewModel.onQrScanned` молча глотает исключения** (`catch (_: Exception) {}`). Теперь внутри есть запись в базу (`PairDeviceUseCase.pair`): если перепривязка упадёт, пользователь ничего не увидит. Нужны хотя бы `AppLogger.e` и сообщение в UI.
4. **Перепривязка при сопряжении не атомарна между таблицами.** `reassignDevice` (tasks) → `deleteDevices` → `clearAll` (task_sync_state) → prefs выполняются отдельными операциями. Повторный скан QR восстанавливает консистентность (шаги идемпотентны), но транзакции нет.

## Тесты

5. **Нет unit-тестов** на:
   - `PairDeviceUseCase`: состав `formerPartners`, перепривязка, сброс watermark и `task_sync_state`;
   - `RestoreBackupUseCase`: замена id, LWW без поднятия `updatedAt`, tombstone неизвестной задачи, отказ для копии партнёра, запись партнёра в `devices` при отсутствии сопряжения;
   - `FormerSelfUseCase`: перепривязка и планирование уведомлений;
   - фильтр устройств в `SyncUseCase.mergeAll`.
6. Тесты на повторяющиеся задачи тоже не написаны (см. `docs/recurring-tasks.md`).

## Функциональность (отложено)

7. **Бэкап не включает настройки:** имя, цвет, тумблеры уведомлений, ежедневная сводка, тумблеры экспериментальных фич. Имя и цвет записаны в `self` файла, но не восстанавливаются.
8. **Бэкап только ручной.** Периодический (WorkManager → выбранная папка) обсуждался и отложен.

## Документация

9. **CLAUDE.md утверждает, что своё устройство не хранится в Room** (раздел «Данные об устройствах — два источника»). На деле `OnboardingViewModel.complete()` пишет себя в `devices`. Новой логике не мешает (свой id везде исключается), но текст неверен.
10. **Таблица «Ключевые файлы» в CLAUDE.md** не содержит `PairDeviceUseCase`, `RestoreBackupUseCase`, `FormerSelfUseCase`, `BackupManager`.
11. **Файл `app/src/main/java/com/familytasks/app/перепривязка.md`** (экспорт диалога) лежит в исходниках. Сборке не мешает; перенести в `docs/` или убрать из репозитория.
